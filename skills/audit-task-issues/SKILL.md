# 任务问题审计

对本轮任务做一次只读、可追溯的执行审计，暴露曾影响执行判断的问题以及未处理事项，并在报告后停止等待用户决定。

## 边界

- 审计范围从最近一次启动当前目标的用户请求开始，到本 Skill 被触发时结束；同一目标的明确追加纳入范围，已经替换的目标与更早的无关任务保持在范围外。
- 默认范围是读取和核查证据，并输出审计结论；文件修改、工具安装、外部系统变更和修复方案实施等待用户明确要求。
- 重跑验证限定为低风险、无外部副作用且与当前任务直接相关的检查；需要写入数据或产生外部影响的验证列为待执行项。
- 报告基于可观察行为、简短决策依据和实际影响；内部思维过程不属于审计证据。

## 收录标准

收录所有实质性问题，包括已经解决的问题，只要它曾经导致以下任一结果：

- 改变原计划、实现路径或任务范围。
- 引入绕过、降级、回退逻辑、重复状态、额外门控或不必要复杂度。
- 缩小验证范围、降低结果可信度或留下未经验证的假设。
- 因系统规则、用户规则、环境、权限或当前范围限制而未处理。
- 被主动判定为与当前任务无关并搁置，即使它没有阻塞当前交付。

命令笔误仅在产生实际影响时纳入；未经调查的偶然迹象标记为未知，结论保持在证据范围内。

## 工作流

1. 确定审计范围。
   写明当前目标、起止边界、用户追加或替换过的范围，以及能够检查的证据来源。

2. 重建实际执行路径。
   对照用户目标与实际操作，记录失败、重试、路径变化、替代实现、跳过的检查、缩小的范围和主动搁置事项；最终命令成功时也保留此前问题。

3. 核验证据。
   证据优先引用错误输出、失败测试、日志、差异和明确执行记录。必要时执行边界允许的只读检查；证据不足时保留未知，结论保持在证据范围内。

4. 标记证据状态。
   - 已确认：有错误输出、失败测试、差异、日志或明确执行记录支持。
   - 推断风险：能从路径变化、复杂绕过或验证缺口合理推断，但尚未证实。
   - 未知：当前上下文不足以判断。

   同时标记处理状态和证据状态；将“已经绕过”按事实记录，并与“已经解决”区分。

5. 解释问题影响。
   对每个问题说明预期状态、实际发生的事情、当时采取的动作或绕过、未立即修复的原因，以及对正确性、完整性、验证可信度和后续维护的影响。

6. 形成根因修复方案。
   优先恢复最早被破坏的不变量，并将修复收敛到正确的责任所有者；修复方案明确删除绕过、回退逻辑、重复状态和额外门控。只有根因修复受权限或范围限制时才提出临时方案，并标注限制原因、残余风险和删除条件。

7. 给出验证方式。
   为每项修复给出能够证明不变量成立的测试、命令或手动场景。区分本轮已执行的验证和仍待授权执行的验证。

8. 输出报告并停止。
   输出报告后等待用户选择继续原任务、按方案修复或结束。

## 输出格式

按以下顺序输出；空项写“无”：

1. **审计范围**：当前目标、时间边界和检查过的证据。
2. **总体结论**：问题数量、当前结果是否可信、是否存在未解决风险。
3. **当前任务问题**：逐项列出状态、证据、被破坏的不变量、当时采取的动作或绕过、未立即修复原因、影响、根因修复方案和验证方式。
4. **范围外发现**：列出主动搁置的问题、证据、范围判断、潜在影响，以及建议的责任所有者和继续处理条件。
5. **修复顺序**：按照阻塞正确性、数据或安全风险、验证可信度、结构复杂度的优先级排序。
6. **待用户决定**：只列需要新权限、扩大范围或产品取舍的事项。

如果实质性问题为零，明确报告“未发现实质性问题”，报告保持在事实范围内。
