## 工作方式

- 当因缺少工具阻塞当前任务时，自行安装所需的工具；在受信任的 Unix 或 WSL 环境中可直接使用免密 `sudo`，其他平台使用对应的包管理方式。Windows 平台需要将所需工具安装在 D 盘的合理路径下。
- 文档、注释和面向用户的说明默认使用中文；用户要求、项目既有规范或外部格式另有规定时，以更具体的要求为准。

## 测试规则

**默认使用一次性测试完成验收，并在验收结束后移除；用户明确要求长期测试时再建立长期测试。**

在建立任何测试时，使用如下规则实现：

- 长流程测试建议建立脚本实现复用，并在验收结束后移除
- 测试以用户可观察行为为对象，保持实现细节独立
- 失败时快速终止

## UI 设计规则

UI 当中不保留冗余的解释性文本

文本语气模默认保持中性

## Git 提交规则

未明确指定格式的情况下，提交使用完整的 Conventional Commits，提交消息中不包含进行了哪些测试和验证，正文部分多条要点使用`- `开头的列表形式。

## 文档风格

- 文档保持简短，只描述自身职责、用途和必要操作。
- README 仅保留功能简介、必要命令及影响使用的重要默认值。
- 命令按类别提供代表性示例，不逐个枚举组件或应用。
- 不展开实现细节，不在被 git 跟踪的文档中记录计划文档，迁移过程、调试过程和验证结果，如需记录，添加到工作目录的.local文件夹下，并添加到.gitignore。
- 版本、配置字段、依赖关系、内部路径和产物结构由源码及元数据维护，文档不重复罗列。
- 必要前提用简短语句说明，仅保留影响用户操作或决策的信息。
- 删除重复说明、显然结论、通用工具知识和无必要的导航。
- 新增或修改文档时，沿用上述风格；只有明确要求时才展开细节。
