# Codex 派发机制

- Codex 使用 `spawn_agent` 派发，使用 `send_message` 传递任务协作消息，使用 `wait_agent` 等待子代理；不要将 Pi 的 `subagent`、`workflowScript`、`runs.run`、`runs.all` 或 `subagent_wait` 当作 Codex API。
- 当前配置最多允许 7 个活跃线程：1 个主代理和最多 6 个并行子代理。并行任务数不得超过 6。
- 子代理使用默认配置；支持参数时显式指定 `agent_type = "default"` 或 `agent_role = "default"`，不支持时省略并由默认配置解析。不要使用 `explorer`、`worker` 或其他非默认角色。
- 每次派发都必须显式设置 `fork_turns = "none"`，避免复制主代理历史，让探子以干净上下文完成自包含任务。
- 多个子代理应在同一轮并发派发；派发后主代理立即调用 `wait_agent`，在所有结果返回前暂停其他分析、检索、命令执行和文件修改。
- 每个探子只使用一轮，不复用或追派。收到结果后，如果系统提供 `close_agent`，应立即关闭已经完成的子代理。
- 子代理通信采用“终态一次性返回”：执行期间不要发送阶段性进度或普通状态消息；完成时只通过一次 `FINAL_ANSWER` 返回结果。
- 子代理运行累计 10 分钟仍未完成时，主代理必须检查状态和运行记录；已有可用结果就采用其有效部分，否则停止该子代理并重新拆分任务。
- 遇到阻塞、错误、权限、安全风险或无法完成时，子代理直接结束本轮，并在 `FINAL_ANSWER` 中说明已查到的内容、未覆盖范围和具体原因，不要先发送阶段性消息。
